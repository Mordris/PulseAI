# M3a Collect Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** `pulse collect` pulls every new item from every enabled collector source in a time window and writes schema-validated results to `runs/<date>/collected/`. A weekly workflow keeps the engine's default source list healthy.

**Architecture:**
- A new `pulseai.collect` package does the work:
  - one shared async HTTP client (hishel cache, per-host rate limits, tenacity retries, robots.txt, size and redirect caps)
  - one runner per collector kind (`rss`, `atom`, `json`, `json-snapshot-diff`, `sitemap`), chosen by the generated registry model's type
  - pure normalization and window functions
  - dated snapshots under `state/snapshots/`
  - an orchestrator that isolates each source's failures and writes outputs atomically
- The registry and output formats are JSON Schemas, like everything else. Python models and TS contracts are generated from them.
- A scheduled workflow runs the CLI against the engine's defaults and keeps one GitHub issue up to date.

**Tech Stack:** Python 3.12+, Typer, Pydantic (generated), httpx 0.28, hishel 1.4, tenacity 9.2, aiolimiter 1.3, anyio 4.15, feedparser 6.0, defusedxml 0.7, trafilatura 2.3, Protego 0.7, courlan 1.4, python-slugify 9.1, nh3 0.3, filelock 4.2, structlog 26.1, vcrpy 9.2; tests: pytest, pytest-recording 0.14, respx 0.23.

**Spec:** `docs/superpowers/specs/2026-10-29-m3a-collect-design.md` (approved 2026-10-29). Parent: `docs/superpowers/specs/2026-10-11-pulseai-daily-research-routine-design.md` §7.4, §11, §15, §16. Read both before starting.

**Scope notes (rulings made while planning; each is cheap to revisit):**
- **`--offline` takes a path:** `--offline CASSETTE` replays a VCR.py cassette with `record_mode="none"`. An unmatched request fails that source with reason `offline_miss`. vcrpy is therefore a runtime dependency of the CLI, so M4's frozen-day evals can use the same replay.
- **Two mocking tools in tests:**
  - **pytest-recording cassettes** for real recorded responses (one representative source per kind).
  - **respx** for synthetic failures (timeouts, retry sequences, header edge cases), which a cassette cannot express.
- **Instance lock:** `filelock.FileLock` on `<instance>/.pulse/collect.lock` with `timeout=0`. The OS releases the lock when a process dies, so the design's "stale timeout" needs no code.
- **Sitemap XML** is parsed with `defusedxml.ElementTree` from bytes fetched by the shared client. trafilatura only reads page metadata (`trafilatura.extract_metadata(html, default_url=url)`), so every request goes through one client (design §16 constraint).
- **Extra mapped fields:** `fields.extra` (an object of JMESPath expressions) copies scalar values into `item.extra`. This is how GitHub's `prerelease` reaches the item (design §8.2) without a fixed field.
- **New config keys** beyond the design's list, all for caps the design asks for in §13:
  - `max_response_bytes`
  - `max_redirects`
  - `max_wait_seconds` (the longest `Retry-After` or rate-limit reset worth waiting for)
  - `title_max_chars`
  - `meta_fetch_limit` (a default for sitemap sources that set none)
  - `max_child_sitemaps`
- **robots.txt follows RFC 9309:**
  - 4xx means allow everything.
  - 5xx or unreachable means disallow everything, and the source fails with `robots_disallowed`.
  - The check only runs when `collect.respect_robots` is true.
- **Kept ids:** the four M1 starter source ids (`claude-code-releases`, `hf-daily-papers`, `arxiv-cs-ai`, `openrouter-models`) keep their ids when they move out of `core.yaml`, because the example reports reference them.

## Global Constraints

Everything in the M1 and M2 plans' Global Constraints still applies:
- latest versions via `uv add` / `pnpm add` without pins
- SHA-pinned actions and workflow hardening (`permissions: {}`, harden-runner first, `persist-credentials: false`)
- no hardcoded values
- schema rules: draft 2020-12, `urn:pulseai:schema:<name>`, `additionalProperties: false`, unique `title`s, no `if`/`then`/`else`
- ids, generated code, and Python/TypeScript style
- Conventional Commits ending with `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`
- CLI output `<level> <where>: <message>` and exit codes 0/1/2
- `ruff format` before `ruff check`

In addition:
- **Every request goes through `Fetcher`** (Task 4), including robots.txt, sitemaps, and sitemap page reads. No other module imports httpx to send a request.
- **No per-source code.** Nothing branches on a source id, host, or URL. Behavior comes from the registry entry, its kind, and `config.collect`.
- **Values live in config or the registry.** Timeouts, limits, lengths, the user agent, and the cache path come from `config.collect` (Task 1 defaults) or the source's `http` block.
- **Fetched content is data.** It is never used as a file path, shell argument, or template. File names come from registry ids and the run date only.
- **Secrets:** auth values are read from the env var a source names, and never appear in output files, logs, exception text, or cache keys.
- **Timestamps** in output files are RFC 3339 UTC with an uppercase `T` and `Z`. Reuse the `timestamp` definition pattern from `schema/report.schema.json`.
- **Untyped libraries:**
  - feedparser and vcrpy ship no types. Add minimal stubs under `typings/` (pyright's default `stubPath`) declaring only what the code uses: `typings/feedparser/__init__.pyi` (Task 5) and `typings/vcr/__init__.pyi` (Task 8).
  - defusedxml uses `types-defusedxml` (a dev dependency).
- **Async tests use AnyIO's pytest plugin.** `packages/cli/tests/collect/conftest.py` defines `anyio_backend` returning `"asyncio"`, and async test modules set `pytestmark = pytest.mark.anyio`. Tests pass `transport=httpx.MockTransport(...)` (from a respx router) or use cassettes, and inject `sleep` so nothing waits.
- **No live network in PR CI.** Tests use cassettes or respx. Live fetches happen only in Task 10 verification and the weekly workflow. Task 5 adds `--block-network` (pytest-recording) to the root `[tool.pytest.ini_options] addopts`, so any test that reaches the network fails.

## Review Focus

1. **Hostile or oversized responses.** A body over `max_response_bytes` must fail the source (`too_large`) without reading it all. A sitemap with entity expansion must be rejected. `<script>` and markup in summaries must never reach output. → Task 4 `test_body_over_cap_fails_too_large`; Task 7 `test_sitemap_entity_expansion_is_rejected`; Task 3 `test_summary_strips_markup_scripts_and_entities`.
2. **Awkward dates.**
   - A timestamp without a time zone is UTC.
   - A date-only value is that day at 00:00Z.
   - The window is `[since, until)`, so an entry dated at or after `until` (including a future date) is dropped.
   - An unparseable date counts as undated.

   → Task 3 `test_parse_timestamp_*`; Task 5 `test_window_bounds_are_half_open`, `test_unparseable_date_is_undated`.
3. **Re-runs and overlap.**
   - Running the same date twice gives identical snapshot and sitemap diffs.
   - A `--source` re-run keeps other sources' summary rows.
   - A second process while the lock is held exits 2.

   → Task 6 `test_same_date_rerun_gives_same_diff`; Task 7 `test_sitemap_same_date_rerun_gives_same_items`; Task 8 `test_partial_rerun_keeps_other_rows`, `test_second_collect_on_same_instance_is_refused`.
4. **Rate limits and flaky upstreams.**
   - 429 with `Retry-After` within budget waits and succeeds; beyond budget it fails `rate_limited` without sleeping.
   - GitHub's 403 with `X-RateLimit-Remaining: 0` counts as a rate limit.
   - 5xx then 200 succeeds.
   - robots.txt 5xx disallows.

   → Task 4 tests of those names.
5. **Credentials.**
   - A token is sent only to its source's request.
   - It never appears in the output files or logs.
   - A response to an authorized request without `public` is not served from the cache to a later request.

   → Task 4 `test_auth_header_only_on_its_source`, `test_authorized_response_not_reused_from_cache`; Task 8 `test_token_never_written_or_logged`.

### Task 4: The shared fetcher

**Files:**
- Create: `packages/cli/src/pulseai/collect/fetch.py`, `collect/log.py`
- Test: `packages/cli/tests/collect/test_fetch.py`
- Dependencies:
  - `uv add --package pulseai httpx hishel tenacity aiolimiter anyio protego structlog`
  - `uv add --dev respx`

**Interfaces:**
- Consumes: `CollectConfig`, `HttpOptions` (Task 1).
- Produces:
  ```python
  FailureReason = Literal["http_error", "timeout", "network_error", "rate_limited", "robots_disallowed",
                          "missing_auth_env", "parse_error", "invalid_items", "too_large", "offline_miss"]
  @dataclass(frozen=True)
  class FetchResult: url: str; final_url: str; status: int; headers: Mapping[str, str]; content: bytes; from_cache: bool; elapsed_ms: int
  class FetchError(Exception):
      def __init__(self, reason: FailureReason, detail: str, *, status: int | None = None) -> None: ...
  class Fetcher:
      def __init__(self, settings: CollectConfig, *, user_agent: str, cache_path: Path | None,
                   host_rates: Mapping[str, int], environ: Mapping[str, str],
                   transport: httpx.AsyncBaseTransport | None = None, sleep: Callable[[float], Awaitable[None]] = anyio.sleep) -> None
  ```

- [ ] **Step 3: Implement `Fetcher`**

- **Client:** one `httpx.AsyncClient(follow_redirects=True, max_redirects=settings.max_redirects, timeout=…)`.
  - Its transport is `hishel.httpx.AsyncCacheTransport(next_transport=transport or httpx.AsyncHTTPTransport(), storage=hishel.AsyncSqliteStorage(database_path=cache_path / "http.sqlite"), policy=hishel.SpecificationPolicy(cache_options=hishel.CacheOptions(shared=True)))` when `cache_path` is set.

- **Rate limits:** one `aiolimiter.AsyncLimiter(rate, 60)` per host.
- **Retries:**
  - `tenacity.AsyncRetrying` with `stop_after_attempt(retries + 1)` and exponential jitter for network errors and 5xx.
  - Rate-limit responses compute their wait from `Retry-After` (seconds or HTTP date) or `X-RateLimit-Reset` (epoch seconds) and call `sleep` when ≤ `max_wait_seconds`. Otherwise they raise `rate_limited` at once.
- **Streaming:** read with `client.stream` and stop past `max_response_bytes`.
- **robots.txt:** a per-host cache of `Protego.parse` results, fetched through the same client and checked against the user agent's product token (`PulseAI`).
- **Auth:** the header name defaults to `Authorization`, and the value is `auth_prefix + environ[auth_env]`.
- **Logging:** log events `fetch`, `retry`, `rate_limit_wait`, `robots_disallowed` through structlog, with the URL and status only, never headers.

`configure_logging` uses `structlog.processors.JSONRenderer` when `json` is true and `ConsoleRenderer` otherwise, writes to stderr, and sets the level to DEBUG when `verbose` is true and WARNING otherwise.

### Task 11: Weekly source-health workflow

**Files:**

**Interfaces:**
- Consumes: the `collect.json` shape (`CollectRun`, Task 1).
- Produces, in `scripts/github/source_health.py`, with the same `gh` subprocess style as `apply_repo_settings.py`:
  ```python
  @dataclass(frozen=True)
  class Broken: id: str; status: str; reason: str | None; note: str
  def broken_sources(current: Mapping[str, Any], previous: Mapping[str, Any] | None) -> list[Broken]
  def issue_body(broken: Sequence[Broken], run_url: str) -> str     # markdown table, one row per broken source
  def main(argv: list[str] | None = None) -> int                     # --current PATH [--previous PATH] --repo OWNER/NAME --run-url URL [--dry-run]
  ```
  - **Broken** means `failed` with any reason except `missing_auth_env`, or `empty` in both `current` and `previous`.
  - With broken sources, `main` creates the issue, or edits the open one found by `gh issue list --label source-health --state open --json number`.
  - With none, `main` closes the open issue with a comment.
  - `--dry-run` prints the `gh` calls without running them.
